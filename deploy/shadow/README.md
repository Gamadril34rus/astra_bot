# Offline shadow replay sandbox

This profile is **offline only**. The replay container cannot reach BingX, Telegram, GitHub, the host network or a local exchange service.

## Runtime boundary

- Container network: `network_mode: none` (loopback only; no external interface/default route).
- Repository: mounted at `/workspace:ro`.
- Writable bind mount: only the caller-supplied external `ASTRA_SHADOW_DATA` directory at `/data:rw`.
- Root filesystem: read-only; `/tmp` is a small tmpfs.
- Process: numeric unprivileged UID/GID 65532; all Linux capabilities dropped; `no-new-privileges`; PID and memory limits.
- No Docker socket, credentials, environment secrets, host PID, host network or privileged mode are mounted/enabled.
- The replay program itself imports no HTTP, WebSocket, broker or private-client package.

## Host preflight

Use the repository launcher; do not invoke Compose directly for a replay:

```sh
mkdir -p /absolute/path/to/astra-shadow-data
chown 65532:65532 /absolute/path/to/astra-shadow-data
chmod 0700 /absolute/path/to/astra-shadow-data
export ASTRA_SHADOW_DATA=/absolute/path/to/astra-shadow-data
```

Place an independently reviewed JSONL event tape at `$ASTRA_SHADOW_DATA/events.jsonl`. No event tape is included or generated by this PR. The launcher canonicalizes the host path and refuses a path inside the repository; it also refuses symlinked or multiply-linked event/state/output files. The data directory must be dedicated to this replay and must not contain links to repository files. A host administrator must ensure that the external directory is not a bind mount, hard-link farm, or other alias of the working checkout. The repository mount itself remains read-only in the container.

The image must already exist locally because the launcher passes `--pull never`; it will not ask Docker to download an image. Before an experiment, pin and record the exact image digest and Docker/Compose versions. The current compose reference uses the mutable `python:3.11-slim` tag, so reproducible image pinning is still a release prerequisite.

Run the replay:

```sh
deploy/shadow/run-offline.sh
```

It reads `events.jsonl`, persists the restart checkpoint and appends results only under `/data`. Optional command arguments are forwarded to the replay CLI. The public candle capture program is not invoked by this profile and has no public-data collector bundled into the replay image.

## Runtime verification

Run the runtime verifier through the same host path preflight:

```sh
deploy/shadow/run-offline.sh --verify
```

The verifier checks effective UID, zero effective capabilities, `NoNewPrivs`, read-only root and repository mounts, writable data mount, tmpfs /tmp, and absence of non-loopback interfaces/default route. It also attempts a temporary write to the repository (must fail) and to `/data` (must succeed and is removed).

These checks attest to the **observed container process** under the supplied Docker daemon/configuration. They do not prove the Docker host/kernel is uncompromised, that an administrator cannot override the profile, or that a future capture network is safely restricted. Runtime verification must be executed on the actual host and its output retained before experiment approval. A network-enabled capture would require a separately approved egress proxy/firewall allowlist and a shared BingX request-budget coordinator; it is intentionally not defined here.

## Evidence status

The Compose profile, host preflight launcher and runtime verifier are prepared in this PR. The runtime verifier has **not** been executed in an actual container during PR development (Docker CLI/runtime is unavailable in the development environment). Evidence currently remains configuration/code-level, not a runtime attestation. This profile is incapable of public market-data collection while `network_mode: none` is enforced.
