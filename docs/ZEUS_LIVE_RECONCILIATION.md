# Сверка закрытых позиций и Telegram-карточек Zeus (VST)

Документ описывает только DEMO/VST live-loop. REAL-маршрут, торговые сигналы,
сайзинг, плечо и риск-параметры этим механизмом не меняются.

## 1. Источники закрытия и PnL

Источники проверяются в порядке надёжности:

1. **Fill history** (allFillOrders / fillHistory): исполнения, относящиеся
   к конкретной hedge-ноге. Сторона и trade IDs должны быть однозначны.
2. **Income history**: строки REALIZED_PNL, комиссии и funding. Строки без
   достаточной привязки к positionSide/trade IDs нельзя приписывать LONG или
   SHORT только по совпадению времени или суммы.
3. **BingX Position History** (/openApi/swap/v1/trade/positionHistory):
   позиционный fallback, когда fill history пустая, а income неоднозначен.
   Совпадение принимается только при единственной записи с теми же symbol,
   positionSide и openTime в пределах 120 секунд от времени фактического входа.
   Время берётся из неизменяемого event=entry в zeus_live_trades.jsonl; для
   старых записей без такого события используется opened_at_ms/since_ms плана.

Для Position History используются netProfit, positionCommission,
totalFunding, avgClosePrice и positionId. netProfit уже включает комиссии и
funding; в журнале pnl хранится как netProfit - totalFunding, а funding_fee
остаётся отдельным signed-полем. Поэтому итог: net = pnl + funding_fee.
avgClosePrice сохраняется как фактическая средняя цена закрытия и передаётся
в exit-card.

Если записей нет, совпадений несколько, сторона не совпадает или время открытия
не попадает в допуск, сделка остаётся pending. PnL не угадывается.

Ограничения биржевого endpoint: Position History относится к закрытым позициям,
доступна в пределах истории биржи (до одного месяца) и требует Hedge Mode;
для One-way Mode этот fallback не считается источником подтверждения.

## 2. Семантика pending

sync_closed_plans pending_fill=[...] означает: биржевая сверка не видит
открытую позицию, но точные данные закрытия/PnL ещё не собраны. Локальный план
временно сохраняется для бухгалтерской сверки. Это не само по себе доказательство
открытой биржевой позиции или отсутствия стопа.

positions=0 orders=0 — снимок биржи на конкретный момент: открытых позиций и
открытых ордеров в этом ответе не было. Для последующего состояния нужен новый
снимок.

income_backfill unresolved означает, что найденные начисления нельзя безопасно
сопоставить с одной hedge-ногой. До появления однозначного источника карточка
не отправляется с выдуманным PnL.

## 3. Доставка Telegram

У подтверждённого выхода два независимых результата:

- card_sent — отправлена визуальная exit-card;
- followup_sent — отправлено текстовое сообщение.

Если один компонент не доставлен, pending-очередь сохраняет только незавершённую
часть. Повторная попытка не должна дублировать уже доставленную часть. Подтверждённые
выходы из fills, income и position_history могут быть повторно доставлены
через resolve_pending_dogon.

## 4. Частота запросов позиций

get_positions() объединяет повторные read-only запросы в пределах одной секунды
внутри процесса. После успешного MARKET-ордера снимок инвалидируется. После
BingX 100410 повторные запросы к endpoint позиций в течение 15 секунд завершаются
локально, без повторного обращения к бирже. Ошибка API никогда не подменяется
пустым списком позиций.

## 5. Диагностические строки

| Строка | Значение |
|---|---|
| sync_closed_plans ... pending_fill | Закрытие на бирже обнаружено, PnL пока не подтверждён |
| sync_closed: ... Position History ... | Получено однозначное совпадение по закрытой позиции |
| dogon position_history ... | Попытка восстановить старый pending-выход |
| income_backfill unresolved | Income нельзя безопасно привязать к hedge-ноге |
| viz_error ... EXIT_CARD | Не удалось отправить картинку; подтверждённый выход ставится на повтор |
| positions endpoint is in local 100410 cooldown | Временный fail-fast после биржевого cooldown |

Все изменения в этом документе относятся к сверке и доставке уведомлений. Они не
дают разрешения включать REAL, менять торговую стратегию или менять риск.
