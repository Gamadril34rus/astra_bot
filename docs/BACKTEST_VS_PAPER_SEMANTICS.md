## 1. Два контура, две семантики «текущего» бара

### 1.1 Бэктестер: «текущий» бар уже закрыт

Бэктестер идёт по историческим свечам и на каждом шаге считает текущий бар
ПОЛНОСТЬЮ ЗАКРЫТЫМ: стратегия видит его OHLC, вход исполняется по его close.

`astra_bot/backtester/engine.py:336-345` (`_process_tick`):

```python
def _process_tick(self):
    """Обработать один тик (свечу)"""
    candle = self._candles[self._current_idx]
    timestamp = candle["open_time"]
    current_price = Decimal(str(candle["close"]))
```

Стратегии получают срез, ВКЛЮЧАЮЩИЙ текущий бар
(`astra_bot/backtester/engine.py:353-355`):


Вход — по close этого же бара (`astra_bot/backtester/engine.py:427-460`,

Порядок внутри тика: сначала проверка выходов по открытым позициям, потом


Это корректная семантика для истории: исторические свечи из
`data_loader` — закрытые бары, «формирующегося» бара в бэктестере нет
по построению.

### 1.2 Live/paper: последний бар фида — формирующийся

Биржевой фид klines отдаёт текущий незакрытый бар последним. После
бэклога A5 (PR #69) входные сигналы строятся ТОЛЬКО по закрытым барам —
формирующийся бар вычитается (`astra_bot/decision/pipeline.py:118-127`):

```python
    @staticmethod
    def _closed_entry_candles(candles: list) -> list:
        """А5: свечки для ВХОДОВ без формирующегося бара.

        Фид klines биржи отдаёт текущий незакрытый бар последним;
        сигнал, построенный на нём, «плывёт» вместе с закрытием.
        Для генерации входных сигналов используем только закрытые
        бары. Выходы не затрагиваются (они на живой цене).
        """
        if len(candles) > 1:
            return candles[:-1]
        return list(candles)
```

Применение — только в генерации кандидатов (`astra_bot/decision/pipeline.py:151-157`):

```python
                # Бэклог A5: ВХОДЫ только по закрытым барам. Последняя
                # свеча в фиде klines — формирующийся бар (close ещё
                # меняется); до фикса стратегии строили входной сигнал
                # по нему. Вычитаем его ТОЛЬКО для генерации сигналов:
                # выходы/трейлинг/стопы работают по живой цене
                # (broker/exit_manager/market safety) — они не тронуты.
                candles = self._closed_entry_candles(candles)
```

## 2. В чём теперь РАЗЛИЧИЕ (после A5)

После A5 семантики сигнала выровнены: оба контура строят входной сигнал
по закрытым барам. ОСТАЮТСЯ два систематических различия исполнения:

| Аспект | Бэктестер | Live/paper | Следствие |
|---|---|---|---|
| Момент сигнала | close бара N | close бара N (тот же: `candles[:-1]` на сессии, открывшейся в начале бара N+1) | совпадает |
| Цена входа | close бара N + slippage 0.1% (`engine.py:456-461`) | живая цена в начале сессии (бар N+1, до 5 минут позже) + slippage | сдвиг входа на один бар по времени, цена может отличаться |
| Выходы | внутри бара N+1… по его OHLC (`_check_exit_conditions`) | по живой цене/живому бару на каждой 5-минутной сессии (`trading_engine.py:1043`, `broker.update_extremes` + `check_exits`) | live реагирует быстрее; бэктест — консервативнее по гранулярности |

## 3. Издержки: вторая часть расхождения

Сравнение PnL бэктеста и paper искажается не только таймингом:

| Компонент | Бэктестер | Live/paper broker |
|---|---|---|
| Комиссия вход | 0.1% (`maker_fee_rate`, `BacktestConfig`) | 0.05% taker (`cost_model.py:244-258`) |
| Комиссия выход | 0.1% `taker_fee_rate` — **начисляется с 13.09.2026** (PR #73) | 0.05% taker на выход |
| Slippage | 0.1% на вход И на выход — **с 13.09.2026** (PR #73) | 0.1% на вход и на выход |
| Сайзинг | по эффективной цене входа (со slippage) — с 13.09.2026 | по эффективной цене входа — с 13.09.2026 (аудит A2) |
| Фандинг | отсутствует (grep `funding` по `astra_bot/backtester/` — 0 вхождений) | начисляется при каждом закрытии — см. B11 |

Итого на круг: бэктестер ~0.4% (0.1% вход + 0.1% выход + 0.2% slippage),
paper ~0.3% (0.05+0.05+0.1+0.1) **плюс фандинг**. Прежнее системное
преимущество бэктеста (~0.1 п.п. на круг) закрыто PR #73: остаточные
различия — фандинг (только у paper) и ставка комиссии входа
(maker 0.1% в бэктесте против taker 0.05% в paper).

**Семантика `exit_price`** (различие контуров, фиксируется сознательно):
в paper `ClosedTrade.exit_price` — ЦЕНА ТРИГГЕРА (уровень стопа/тейка),
фактическое исполнение (±slippage) живёт внутри `_pnl_with_fees`; в
бэктестере с 13.09.2026 `Trade.exit_price` — фактический fill
(уровень ± slippage). При сверке сделок из двух контуров это надо
учитывать: цены отличаются на величину slippage, а не на ошибку.

### 3.1 Гэп сквозь уровень не моделируется (аудит A3, 13.09.2026)

Оба контура исполняют стоп/тейк **по цене уровня ± slippage**, а не по цене,
которая реально была на рынке после гэпа:

- paper: триггер по `high`/`low` бара, исполнение — `effective_exit_price`
  (уровень ±0.1%) в `astra_bot/decision/broker.py:941-948`;
- бэктестер (после PR «execution costs»): `raw_exit_price * (1 ∓ slippage)`
  в `astra_bot/backtester/engine.py:_close_position`.

Следствие: хвост убытков глубже 1R недооценивается — например, в paper-статистике
встречается `min R = −2.04` при стопе 1R (`docs/TAKE_RR_FEASIBILITY.md:44`,
«гэп-исполнение стопа … отдельный факт для контроля»). Ни один из контуров
не претендует на моделирование проскальзывания сквозь уровень; для оценки
риска хвоста нужна отдельная модель исполнения (вне текущего объёма).

## 4. Решение (B10)

Фиксируем различие документально; выравнивание кода НЕ делаем, потому что:

1. Семантика сигнала уже выровнена A5 — главный источник «бэктест
   торгует то, чего нет в live», устранён (входы по закрытым барам там
   и там).
2. Цена входа «close сигнального бара» в live недостижима: CI-сессия
   бота стартует раз в 5 минут (`bot.yml`: `BOT_LISTEN_SECONDS=200`),
   вход физически происходит по живой цене следующего бара. Задержать
   бэктест-вход до open бара N+1 можно, но это меняет результаты всех
   существующих прогонов — отдельная research-задача (блок C), не гигиена.
3. Издержки — см. таблицу §3 и `docs/COST_MODEL.md`. PR #73 (13.09.2026)
   выполнил часть унификации: комиссия выхода, slippage на выход и сайзинг
   по эффективной цене входа. Открытым остаётся фандинг в бэктестере
   (замер влияния — `docs/FUNDING_BACKTEST_VS_PAPER.md`, блок B11) и
   ставка комиссии входа; это по-прежнему блок C, а не гигиена.

## 5. Что наблюдать после мержа

- Ничего в поведении бота не меняется — PR документальный.
- При сравнении прогонов бэктеста с paper-результатами учитывать:
  +0.1 п.п. издержек на круг в пользу бэктеста (§3) и сдвиг входа на
  один бар (§2). Правило большого пальца: расхождение результатов до
  ~0.5% на сделку — шум семантики, дальше — искать реальную причину.
