# D5: входы против старшего таймфрейма — инвентаризация и план фильтра

> Статус: ОТЧЁТ + ПЛАН (код НЕ меняется — P2, исследование).
> Правило владельца: «В боковике и не только сначала смотреть с большего
> времени, до 5 минут» — вход на младшем ТФ не против направления
> старшего. Сегодня общего правила НЕТ.

## 1. Инвентаризация: кто сейчас определяет направление входа

### 1.1 Все стратегии пайплайна видят ТОЛЬКО один ТФ

Пайплайн передаёт стратегии срез ОДНОГО таймфрейма: preferred, если
задан, иначе primary = 5m → 15m → 1h → 4h
(`astra_bot/decision/pipeline.py:144-150`):

```python
        for strategy in self.strategies:
            try:
                # Стратегия может запросить конкретный таймфрейм
                # (например, ts_momentum оценивается на 4h-свечах).
                preferred_tf = getattr(strategy, "preferred_timeframe", None)
                if preferred_tf and ctx.candles_on(preferred_tf):
                    candles = ctx.candles_on(preferred_tf)
                else:
                    candles = primary
```

preferred_timeframe в продакшен-наборе задан ТОЛЬКО у ts_momentum — 4h
(`astra_bot/strategies/ts_momentum.py:79`):

```python
    preferred_timeframe: str = "4h"
```

Остальные — momentum, mean_reversion, pullback, scalp, scalp5m, 18
паттернов-адаптеров (`trading_engine.py:185-335`: `MeanReversionStrategy,
MomentumStrategy, PullbackStrategy, Scalp5mStrategy, ScalpStrategy,
TimeSeriesMomentumStrategy` + `PipelineStrategyAdapter(...)`) — оцениваются
на primary (5m, фолбэк 1h): старшие ТФ в их решении НЕ участвуют.

### 1.2 «Режим рынка» — тоже не старший ТФ

Режим для гейтов и `market_regime`-параметра стратегий считается по ТЕМ
ЖЕ primary-свечам (`astra_bot/decision/pipeline.py:245-251`):

```python
        # 2. Regime.
        regime = self.regime.classify(
            primary,
            news_score=ctx.news_score,
            btc_regime=ctx.global_market.get("btc_regime"),
```

То есть даже скрытый фильтр «режим против входа» в проде работает на 5m.

### 1.3 Кто ЕСТЬ с MTF-логикой — вне продакшен-пайплайна

`multicurrency_mtf` имеет 1D-гейт EMA20/50/200
(`astra_bot/strategies/multicurrency_mtf.py:122` — проверено в прошлом
аудите), `ts_momentum` — 4h-импульс (45 дней), но это ФЛИП-стратегии
(режим целиком, входы обеих сторон — по дизайну исключение из правила).
В проде из них ts_momentum(+cross) — да; multicurrency_mtf — нет
(исследовательская). Итог: **в продакшен-наборе нет ни одной НЕ-флип
стратегии, которая сверяется с 1h/4h перед входом.**

### 1.4 Что это значит на цифрах

Текущий поток сделок — преимущественно 5m/15m входы в обе стороны
(123 сделки за 3 дня; медианное удержание 25 мин). Доля входов против
1h/4h-тренда НЕ измерялась — это первый шаг плана (ниже): замер в
shadow-режиме без блокировки.

## 2. План глобального directional-фильтра (НЕ-флип стратегии)

Принципы: единая точка, только закрытые бары старших ТФ (А5-семантика),
fail-open при недостатке данных, флипы не трогаем (их режим — сам фильтр).

1. **Точка**: `DecisionPipeline.decide` — до перебора стратегий; данные
   уже в контексте (`ctx.candles_on("1h"/"4h")`).
2. **Правило (v1)**: направление 4h по EMA20/50 (по образцу гейта
   multicurrency_mtf.py:122): long запрещён, если 4h EMA20 < EMA50 и
   close < EMA50; short — зеркально. 1h — подтверждение или отдельный
   ослабляющий порог (например, блок только при совпадении 1h+4h).
3. **Режим внедрения**: фаза 0 — SHADOW (решение пишется в
   `no_trade_observations.jsonl` как гипотетический запрет, входы живут);
   через 2 недели — замер «сколько запретов, какой был бы PnL без них»;
   фаза 1 — включение блокировки конфигом (флаг, дефолт off).
4. **Кто не под фильтром**: стратегии с флагом `is_flip = True`
   (ts_momentum, ts_momentum_cross — их сигнал и есть смена направления
   старшего ТФ) — список имён, не атрибут, чтобы не плодить состояния.
5. **Fail-open**: < 60 закрытых баров 4h или ошибка расчёта — фильтр
   молчит (входы не блокирует), событие в лог — как остальные
   alpha-фильтры (приёмка «alpha fail-open, safety отдельный»).
6. **Метрика успеха фазы 0**: у сделок, которые фильтр ЗАПРЕТИЛ БЫ,
   средний R значимо ниже общего (цель: −0.3R у запрещённых против
   −0.33 общего — на образце 123 сделок различимо плохо; нужно 300+).

## 3. Что наблюдать

- После фазы 0: доля «запрещённых бы» сделок по дням и их суммарный R —
  в еженедельном разборе.
- Не внедрять фазу 1 до 300+ сделок в выборке (шум).
