# Прибыльная стратегия (Parabolic SAR) — заметка для внедрения

**Дата фиксации:** 2026-11-17  
**Обновлено:** 2026-11-17 (вечер) — полные издержки бота + профиль max-result  
**Статус:** исследование / кандидат в бот (ещё НЕ включена в live ASTRA)  
**Биржа:** BingX USDT-M Perpetual Futures

> Цифры — из исторических прогонов. Не гарантия будущей доходности.

---

## 1. Суть стратегии

- Точки SAR **под** ценой → long после закрытия свечи.  
- Точки SAR **над** ценой → short после закрытия свечи.  
- Стоп = точка SAR (трейл каждый бар). Тейка нет — выход по касанию стопа.  
- Размер позиции: **риск % от equity до стопа** (не «маржа × плечо»).  
- Плечо только как **потолок**. В модели при таком сайзинге **ликвидаций не было**.

**Параметры SAR (база):** start=0.02, increment=0.02, maximum=0.2  
**Таймфрейм для max-result:** 1h  
**Монеты:** BTC, ETH, SOL (1h). 15m в длинных тестах с бот-издержками результат портил.

## 2. Издержки — как в демо-боте (обязательно)

Источник: `astra_bot/engines/cost_model.py` → `bingx_perps_cost_model` + `docs/COST_MODEL.md`.

| Статья | На сторону | Round-trip |
|--------|------------|------------|
| Taker fee | **0.05%** | **0.10%** |
| Slippage (paper) | **0.1%** | **0.20%** |
| **Итого fee+slip** | | **~0.30%** на сделку |

Раньше в части прогонов slippage был 0.03% — это **завышало** прибыль.  
Актуальные цифры ниже — **только с 0.05% + 0.1% slip**.

---

## 3. Что НЕ считать улучшением ради денег

Пробовали: EMA50, фильтр объёма, часы EU/US, breakeven, time-stop, slow SAR, только long/short.

| Идея | Влияние на **финальную сумму** |
|------|-------------------------------|
| EMA50 + объём | Сильно **режет** финал (с ~206к до ~48к с 5к за год) |
| Breakeven / time-stop | Хуже |
| 15m в общий портфель на длинной дистанции | Хуже / слив |
| Фильтры «для меньшей просадки» | Меньше DD, **меньше денег** |

**Вывод владельца:** цель — результат в деньгах; просадка <50–67% без ликвидации приемлема.  
Фильтры ради DD **не** фиксируем как основной путь.

Период: ~1 год (≈333–375 дней 1h), BTC+ETH+SOL, SAR std, min_prev=0, без EMA/vol фильтров.

| Профиль | Риск / сумма | Финал с 5000 ₽ | Доходность | Макс. DD | Ликвидации |
|---------|--------------|----------------|------------|----------|------------|
| BASE | 1% / 3% | **~270 000 ₽** | +~5300% | **−41%** | нет |
| Активнее | **1.25% / 5%** | **~617 000 ₽** | +~12 200% | **−49%** | нет |
| Агрессив | **1.5% / 6%** | **~1 330 000 ₽** | +~26 400% | **−56%** | нет |

Для сравнения (тот же период, бот-издержки):

EMA-версия **хуже по деньгам** → не основной кандидат.

## 5. Профили для дальнейшего разбора

### A) BASE money (основной под результат)

- SAR 0.02/0.02/0.2, 1h  
- BTC + ETH + SOL  
- min_prev = 0 (не резать серии)  
- Без EMA / volume / hour фильтров  
- Риск **1%** или **1.25%** на сделку  
- Суммарный потолок **3–5%**  
- Плечо-потолок 3–5× (размер от стопа)  
- Стоп только SAR  

Ориентир с 5к за ~год в модели: **~270к (1%)** или **~617к (1.25%)**.

### B) Агрессивный (если сознательно принимаем DD 55%+)

- То же, риск **1.5%**, сумма **6%**  
- Ориентир с 5к: **~1.3 млн** в модели, DD ~−56%

### C) Не использовать как основу

- EMA50 + volume (меньше денег)  
- 15m в длинном портфеле с этими издержками  
- Плечо «ради плеча» без пересчёта риска до стопа  

---

## 6. Правило размера позиции

```
риск_в_деньгах = equity × risk_per_trade
дистанция_стопа = |entry − SAR| / entry
notional = риск_в_деньгах / дистанция_стопа
# плечо = notional / equity  ≤  max_leverage_cap
```

Если новый сигнал поднимает сумму открытых risk_frac выше потолка — **пропуск**.

---

## 7. Старые цифры (до полных бот-издержек) — справочно

Часть ранних цифр считалась со **slippage ~3 bps**, не 0.1%. Они **оптимистичнее** реальности бота.  
Не использовать для ожиданий live/demo без пересчёта.

Примеры (устарели для бота):
- короткий 5-монетный тест 1%/5%: +1272%, DD −16% (slip занижен)  
- длинный 1h без жёсткого slip: очень высокие %  

**Актуальная правда для бота:** раздел 4.
