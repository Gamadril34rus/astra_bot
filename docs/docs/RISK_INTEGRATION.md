# Risk Engine в живом paper-контуре

Состояние на 2026-08-28. Реализация требований master prompt §11 (независимый
риск-слой), §12 (sizing от риска), §24 (реальные издержки в paper).

## Что было

`RiskEngine` (`astra_bot/engines/risk_engine.py`) существовал, но живой
paper-контур (`TradingEngine` → `PaperBroker`) его **не вызывал**: дневные и
недельные лимиты потерь, просадка и TRADING HALT не применялись к фактической
paper-торговле. Размер позиции считался в `TradingEngine._position_size`
сам, уроки писались без учёта комиссий.

## Что изменилось

1. **Risk Engine в execution path.** `TradingEngine` создаёт `RiskEngine`
   (лимиты согласованы с торговым конфигом: risk/trade, max positions,
   max exposure) и прогоняет каждую потенциальную сделку через
   `check_trade` перед открытием:
   - дневной/недельный лимит потерь → вход запрещён;
   - hard/emergency drawdown → `TRADING HALT` (`trading_enabled=False`),
     новые входы запрещены, выходы (стопы/тейки/CLOSE/FLIP) продолжаются;
   - превышение risk-per-trade или exposure → размер уменьшается до лимита
     и проверяется повторно (до 2 итераций);
   - каждая закрытая сделка идёт в `record_trade`, открытая — в книгу
     позиций движка.

2. **Живое состояние между CI-сессиями.** GitHub Actions поднимает свежий
   процесс каждые ~5 минут, поэтому `RiskEngine.restore_from_trades()`
   пересобирает дневной/недельный PnL, high water mark и HALT-статус из
   `models/paper_trades.jsonl` (источник истины уже персистится в
   `bot.yml` — новый state-файл не введён). Восстановление происходит
   однократно за сессию в `_sync_risk_state()` перед первым `process_symbol`.

3. **Исправлен баг скользящих окон.** `_daily_pnl`/`_weekly_pnl` раньше
   только накапливались и никогда не сбрасывались — дневной лимит
   срабатывал «навсегда». Теперь `_cleanup_old_trades()` пересчитывает PnL
   окон из фактически оставшихся сделок (24ч / 7д).

4. **Реальные издержки в paper-счёте.** `PaperBroker` считает эффективную
   цену входа/выхода с учётом `slippage_pct` и тейкер-комиссию `fee_pct`
   с обеих сторон (по умолчанию 0.1%/0.1% — baseline audit из
   `run_full_research_audit.py`). `ClosedTrade.fees` фиксирует издержки
   отдельным полем; комиссии попадают в уроки. Legacy-позиции без
   `fill_price` восстанавливаются с `fill_price=entry_price` и нулевой
   входной комиссией.

## Что НЕ изменилось (осознанно)

- Сетапы стратегий, логика тейков/трейлинга и `MarketSafety` (расписание,
  новости, спред, волатильность) — риск-слой дополняет их, а не заменяет.
- `TRADING HALT` по просадке не снимается автоматически: восстановление —
  только ручным решением (в соответствии с политикой «никаких попыток
  отбить убыток»). Для сброса: удалить/обнулить состояние и перезапустить,
  либо дождаться, когда история сделок выйдет из окна просадки.
- Web-сервис `main.py` (PaperTradingEngine) — отдельный контур, риск-слой
  туда не переносился (он не исполняет live-ордера).

## Тесты

- `tests/unit/test_risk_engine.py` — скользящие окна 24ч/7д (регрессия
  накопления), `restore_from_trades` (окна, кривая капитала, HWM, HALT).
- `tests/unit/test_paper_broker.py` — fee/slippage-учёт (long/short,
  частичные тейки, legacy-состояние).
- `tests/unit/test_trading_engine_risk.py` — реальный execution path
  `process_symbol`: чистое состояние → вход; дневной лимит → блок;
  просадка 9% → HALT; недельный лимит (в окне / вне окна); закрытая
  сделка → обновление дневного PnL и книги позиций.
